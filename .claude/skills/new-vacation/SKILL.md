# Add a vacation to vacation3d

This is done rarely, so ask rather than guess. One question block at a time, wait for the answer,
then continue. The data model is: `raw/<id>/*.gpx` (gitignored) + a small config json you write
from the answers (kept outside the repo, e.g. in the scratchpad) → `clean_tool/clean_gpx.py --config`
→ `data/<id>.js`, the ONE committed file per vacation. It embeds the config, so later reruns
(`clean_gpx.py --id <id>` without `--config`) keep POIs, names and camera. The PHP plugin file is
generated by `build_plugin.sh` from `src/plugin.php.template`; never write content into PHP.

## 1. Id and GPX files

Ask for a short id (lowercase ascii, e.g. `vilnoess`) and where the GPX files are. Copy them to
`raw/<id>/`. Ask what the trip is (title, dates) for the json `title`/`description`.

## 2. Day split — confirm with the user

Run `python3 clean_tool/clean_gpx.py --id <id>` (works without a config yet). It prints one line per
day with source file, points, km, ascent/descent and start–end time, then the breaks. Show that
table and ask: *are these the days as you remember them?* Typical problems and fixes:

- one file contains several days, or several files make one day → `"days": "date"` in the
  config (or `--by-date`), which pools all points and splits by calendar date
- a file with a few stray points from the previous evening → already handled (gap > 3 h at the start)
- a day that should not be shown → delete/move that file out of `raw/<id>/`

## 3. Breaks — ask for each one whether it gets a label

For every printed `break: day D HH:MM UTC, N min, E m` ask: hut name / place, or leave it as an
unnamed pause? Named ones go into the config as `"breaks": { "D:N": "Label" }` (day:minutes) and
render orange with a label; unnamed ones stay small red dots. If two breaks sit at the same spot
(same coordinates a few minutes apart) point that out; usually only the longer one gets the name.

## 4. POIs

Ask for the places that must be labelled: huts, start, end, bus stops. For each: label, and
either coordinates (lat, lon — the user often pastes "lat, lon" from Google Maps; the config wants
`lon` and `lat` as separate numbers) or "start/end of day N" → `{ "label", "track": N-1, "at": "start"|"end" }`
(track index is 0-based). Offer the day starts/ends as candidates.

## 5. Camera and colours, then write the config and run the cleaner

`overview` = center (lon, lat of the track bbox centre), zoom ≈ 12.5, pitch ≈ 58, bearing so the
camera looks *along* the main ridge (ask which side the viewer should stand on, or take 160 like
Villnöß). `follow` = `{ "zoom": 13.4, "pitch": 62 }`. One colour per day. Write the config json
to the scratchpad and run the cleaner with it. This is the complete example of Villnöß:

```json
{
  "title": "Villnöß – Geisler-Umrundung 2026",
  "description": "3 Tage Hüttenwanderung um die Geislerspitzen, Villnößtal, August 2026.",
  "days": "file",
  "pois": [
    { "label": "Guggan (Bus)",        "lon": 11.794135, "lat": 46.661176 },
    { "label": "Edelweißhütte",       "lon": 11.768567, "lat": 46.666813 },
    { "label": "Gampenalm",           "track": 0, "at": "end" },
    { "label": "Brogleshütte",        "track": 1, "at": "end" },
    { "label": "St. Magdalena (Bus)", "track": 2, "at": "end" }
  ],
  "breaks": { "2:54": "Geisleralm", "3:28": "Waldschenke" },
  "colors": ["#ff3b1f", "#ffb020", "#25d0ff"],
  "secondsPerDay": 20,
  "exaggeration": 1.3,
  "overview": { "center": [11.762, 46.636], "zoom": 12.6, "pitch": 58, "bearing": 160 },
  "follow":   { "zoom": 13.4, "pitch": 62 }
}
```

Optional: `"pluginName": "Villnoess"` if the automatic plugin name (title before the dash,
umlauts transliterated) is not wanted.

```bash
python3 clean_tool/clean_gpx.py --id <id> --config /path/to/<id>.json
```

Then serve the demo (`python3 -m http.server 8766`, `demo/index.html`, set its `data-vacation`
to the new id or add a second block) and check it in Chrome. Adjust camera until the whole route
is visible; the user decides. To change anything later: rerun with `--config` again, or edit the
`config`/`pois` part of `data/<id>.js` and rerun without `--config`. The animation only runs while
the tab is visible.

## 6. Build ("compile") and deploy

```bash
./build_plugin.sh <id>          # plugins/vacation-3d-map-<id>/ + dist/<slug>.zip, PHP generated from the template
cd ../music_blog && .venv/bin/python -m musicblog.publish plugin-push \
    --source ../vacation3d/plugins/vacation-3d-map-<id> --remote wp-content/plugins/vacation-3d-map-<id>
```

Activate via REST (`POST ?rest_route=/wp/v2/plugins/vacation-3d-map-<id>/vacation-3d-map-<id>`
with `{"status":"active"}`) or wp-admin. Create/update a private test post tagged "private"
containing `<!-- wp:vacation3d/map {"vacation":"<id>","height":600} /-->`, open it in Chrome,
check labels, breaks, camera flight. Optionally set the post header with
`python -m musicblog.publish header <post_id> <image>`.

## 7. Commit

Commit `data/<id>.js` (the only per-vacation file). Raw GPX, plugins/ and dist/ are ignored. Author
"Sebastian Engel-Wolf <sebastian@mail-wolf.de>". Update README "vacations" list if there is one.
